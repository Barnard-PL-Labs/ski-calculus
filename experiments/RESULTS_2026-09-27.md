# MRG health check + FPGA vs Modal cost, 2026-09-27

Two things measured today: (1) does the repo still run end-to-end on the
current MRG stack, and (2) what does a candidate cost on an FPGA board vs
renting CPU cores on Modal.

**What a "candidate" is:** one random well-formed 16-node SKI term, generated,
reduced to WHNF (step cap 2000), and scored against a target truth table (XOR,
n=2, max fitness 4/4). Throughput = candidates evaluated per second.

## 2. Modal CPU throughput

`experiments/modal_cpu.py` runs `cpu_baseline.c` (bit-identical workload,
`-O3`) as N concurrent single-thread processes in one Modal container, one
process per requested physical core:

| Modal cores | throughput | per core |
|---:|---:|---:|
| 1  |    322,754/s | 322,754 |
| 8  |  2,219,623/s | 277,453 |
| 32 | 10,661,828/s | 333,182 |
| 64 | 21,326,536/s | 333,227 |

~**330K cand/s per Modal core**, linear; matches the M4's ~320K/core. (The
script also runs 2x processes per core; those rows are inflated because Modal
lets containers burst past their `cpu` request -- ignore them. Real hyperthread
gain looks like ~1.3x.) CPU model not reported inside the container.

## 3. Cost per candidate

Modal: $0.0000131 / core / s (modal.com/pricing, 2026-09-27); memory < 1%.
FPGA: no live per-board price exists. Used the proposed **dedicated-board SKU,
$50-75/month** (`Manhattan-Reasoning-Cloud/docs/design/stripe-usage-billing-plan.md`),
730 h/month, board busy 100% of the time.

| | $/hour | candidates/hour | $ per million | $ per billion |
|---|---:|---:|---:|---:|
| Modal, 1 core | $0.047 | 1.19 B | $0.000040 | $0.040 |
| FPGA K=40, $50/mo | $0.068 | 8.93 B | $0.0000077 | $0.0077 |
| FPGA K=40, $75/mo | $0.103 | 8.93 B | $0.0000115 | $0.0115 |
| FPGA K=50, $50/mo | $0.068 | 13.4 B | $0.0000051 | $0.0051 |
| FPGA K=50, $75/mo | $0.103 | 13.4 B | $0.0000077 | $0.0077 |

(K=40 = 2.48 M/s, 2026-07-16 measurement; K=50 = 3.72 M/s, README, not
currently buildable.)

A board costs ~2x a Modal core per hour but produces 7.5-11x the candidates,
so **FPGA is 3.5-8x cheaper per candidate** -- if it's busy.

Caveats that matter:
- **Utilization.** A reserved board bills whether or not it runs. Break-even vs
  Modal is ~20-30% busy (K=40) or ~13-19% (K=50). Idle time costs more than
  anything else.
- **Board-sized increments.** Capacity comes in ~2.5 M/s (K=40) or ~3.7 M/s
  (K=50) steps. Worst case (just over one board -> pay for two) is ~$0.022/B,
  still about half of Modal; the rounding loss shrinks as the board count grows.
- **Fill the board.** Price is per board, so always build max K. Fixing
  Cloud#79 (K=50) is worth +50% throughput for the same price.
- Modal wins for bursty or sub-board-sized workloads (per-second billing).
- Owned hardware: ~3 W is ~$0.0005/h of electricity; real cost is board
  amortization (not known -- the ~$40 figure is the FPGA chip alone).

Repro: `modal run experiments/modal_cpu.py`;
`python experiments/measure_throughput.py ski_ga_fpga_k4.py 50`.
